ИИ-ассистенты наиболее полезны, когда усиливают уже существующий процесс, и наименее полезны, когда заменяют суждение, которое вы ещё не выработали.

## Используйте ассистентов для скучной середины

Они блестящи в шаблонном коде, каркасах тестов и переводе решения на третий язык, которым вы владеете неважно. Они слабее всего там, где корректность неочевидна.

> [!IMPORTANT]
> Вы отвечаете за каждую строку, включая те, которые не прочитали внимательно. «Это написал модель» — не ревью кода.

## Процесс, который сохраняет код вашим

1. Сначала напишите интерфейс и тест.
2. Попросите реализацию, удовлетворяющую тесту.
3. Прочитайте каждую строку перед принятием.
4. Коммитьте маленькими проверяемыми шагами.

```bash
git add -p
git commit -m "feat(queue): add idempotent order handler"
```

## Где это стабильно помогает

| Задача | Ценность |
| --- | --- |
| Тесты и фикстуры | высокая |
| Повторяющиеся рефакторинги | высокая |
| Новая архитектура | низкая |
| Логика, чувствительная к безопасности | тщательно проверять |

> [!TRADEOFF]
> Быстрое предложение, принятое вслепую, стоит дороже в отладке, чем написать самому.

## Держите контекст небольшим

Давайте ассистенту релевантные файлы, а не весь репозиторий. Сфокусированный контекст даёт сфокусированный код.
