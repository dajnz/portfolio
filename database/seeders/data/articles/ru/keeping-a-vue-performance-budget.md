Как и любой бюджет, бюджет производительности полезен только тогда, когда измеряется автоматически и ломает сборку при превышении.

## Начните с реальной метрики пользователя

Размер бандла — это лишь косвенный показатель. Важен Largest Contentful Paint на телефоне среднего класса, а на него влияют три вещи:

| Затрата | Типичный виновник |
| --- | --- |
| Парсинг и выполнение JS | большая библиотека компонентов |
| Гидратация | рендер всего сразу |
| Сеть | раздутый чанк вендоров |

> [!IMPORTANT]
> Замеряйте с ограничением CPU. Флагманский ноутбук скрывает именно те регрессии, которые чувствуют ваши пользователи.

## Разделение кода по маршрутам

Роутер — самая чистая точка разделения. Каждая страница тянет только необходимое, и лендинг перестаёт оплачивать админский редактор.

```ts
const routes = [
    { path: '/', component: () => import('./LandingPage.vue') },
    { path: '/blog/:slug', component: () => import('./ArticlePage.vue') },
];
```

## Мемоизируйте дорогое

`computed` достаточно в большинстве случаев. Виртуализируйте только там, где список может расти безгранично.

```ts
const visible = computed(() => all.value.slice(0, page.value * 20));
```

![Бюджет производительности](/assets/demo/articles/performance.svg)

> [!TRADEOFF]
> Агрессивное разделение улучшает первую отрисовку, но добавляет каскад запросов. Группируйте небольшие страницы вместо разделения каждого компонента.

## Держите бюджет в CI

Останавливайте конвейер, а не пользователя. Бюджет в вики — это пожелание; бюджет в CI — это гарантия.
