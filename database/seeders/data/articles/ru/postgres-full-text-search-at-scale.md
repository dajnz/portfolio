В PostgreSQL есть полноценный полнотекстовый движок. Для портфолио или небольшого блога он полностью избавляет от отдельного поискового сервиса.

## Векторы и словари

Колонка `tsvector` хранит лексемы документа. Вычисляемая при записи, она становится единственным источником правды для поиска.

```sql
ALTER TABLE blog_article_translations
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    to_tsvector('simple', coalesce(title, '') || ' ' || coalesce(content, ''))
) STORED;

CREATE INDEX search_vector_idx
ON blog_article_translations USING gin (search_vector);
```

> [!TIP]
> Используйте `simple` для смешанного по языкам контента. Языковой словарь обработает не тот язык и даст неожиданные результаты.

## Ранжирование без шума

Сырой `ts_rank` отдаёт предпочтение длинным документам. Нормализация делит на длину документа, чтобы короткие точные статьи могли побеждать.

| Нормализация | Эффект |
| --- | --- |
| 0 | исходная частота |
| 1 | деление на логарифм длины |
| 32 | деление на длину + 1 |

## Поиск по префиксу для автодополнения

Завершающий `:*` превращает последнюю лексему в префикс — именно то, что нужно строке поиска, пока пользователь ещё печатает.

```sql
SELECT slug
FROM blog_article_translations
WHERE search_vector @@ to_tsquery('simple', 'postgr:*');
```

## Подсветка

`ts_headline` формирует фрагмент с тегами `<mark>`. Держите параметры в одном месте, чтобы все поверхности подсвечивали одинаково.

## Когда идти за поисковым сервером

Если нужны нечёткое сравнение, бустинг по полям в масштабе или команда, занимающаяся релевантностью, — переходите. Для всего меньшего PostgreSQL достаточно и обслуживать его не нужно.
