«Добавить кеш» — это не стратегия. Есть четыре слоя, каждый решает свою задачу, и их путаница — путь к устаревшим данным у пользователя.

## HTTP-кеш

Самый дешёвый запрос — тот, что вообще не доходит до сервера. Неизменяемые ресурсы кешируются на год; HTML требует ревалидации.

| Ресурс | Политика |
| --- | --- |
| Хешированные ассеты | `max-age=31536000, immutable` |
| HTML | `no-cache` |
| Чтение API | короткий `max-age`, ревалидация |

> [!IMPORTANT]
> Кешируйте только то, что умеете инвалидировать. Если не можете назвать событие, очищающее кеш, не добавляйте слой.

## Кеш приложения

Дорогие вычисления попадают в Redis с явным ключом и TTL. Ключи на основе хеша контента инвалидируются сами при изменении содержимого.

```php
$key = "article:html:{$id}:{$locale}:{$contentHash}";
Cache::put($key, $html, now()->addWeek());
```

## Кеш запросов

Короткоживущие кеши в пределах запроса убирают дублирующиеся запросы. Они не должны переживать сам запрос.
