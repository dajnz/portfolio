Redis — не замена базе данных. При осознанном использовании он убирает повторяющуюся работу, которая доминирует в приложениях с высокой нагрузкой на чтение.

## Cache-aside для чтения

Проверьте кеш, при промахе обратитесь к базе, затем заполните кеш. У ключей есть TTL, поэтому пропущенная инвалидация самоизлечивается.

```php
$article = Cache::remember(
    "article:{$slug}",
    now()->addMinutes(10),
    fn () => $repository->findBySlug($slug),
);
```

> [!IMPORTANT]
> Cache-aside безопасен, только если чтение устаревших данных допустимо. Для всего, что связано с деньгами, читайте из источника.

## Счётчики с атомарными инкрементами

Счётчики просмотров и реакции не должны быть «прочитал — изменил — записал». Инкременты Redis атомарны и дешёвы.

| Операция | Команда |
| --- | --- |
| инкремент | `INCR` |
| уникальный посетитель | `PFADD` |
| топ N | `ZINCRBY` |

## Сортированные множества для рейтингов

Сортированное множество поддерживает порядок при обновлении, поэтому «топ-10» — это один запрос диапазона.

![Слои кеширования](/assets/demo/articles/caching.svg)

> [!WARNING]
> Большие множества и сканирование ключей по маске могут заблокировать однопоточный сервер. Предпочитайте явные ключи и ограниченные коллекции.

## Планируйте инвалидацию

Для каждого ключа знайте событие, которое его удаляет. Если такого события нет, вы построили генератор устаревших данных.
