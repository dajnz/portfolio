Очереди выносят медленную работу из цикла запроса. Сложность не в том, чтобы поставить задание в очередь, а в том, чтобы задания оставались корректными при сбое на середине.

## Сначала идемпотентность

Считайте, что каждое задание выполнится минимум один раз. Сохраните естественный ключ и сделайте обработчик безопасным для повтора ещё до добавления логики ретраев.

```php
public function handle(OrderId $order): void
{
    if ($this->processed->has($order)) {
        return;
    }

    $this->process($order);

    $this->processed->put($order, true);
}
```

> [!WARNING]
> Повтор — это не откат. Внешние побочные эффекты, которые уже произошли, нельзя отменить проигрыванием задания.

## Повторы и отсрочка

Экспоненциальная отсрочка даёт сломанной зависимости время восстановиться вместо того, чтобы бомбить её запросами.

| Попытка | Задержка |
| --- | --- |
| 1 | 1 мин |
| 2 | 5 мин |
| 3 | 30 мин |

## Очередь «мёртвых» заданий

После последней попытки задание должно попасть в надёжное и заметное место. Очередь мёртвых заданий, которую никто не читает, — просто более дорогой лог.

![Надёжность очередей](/assets/demo/articles/queues.svg)

> [!TIP]
> Отслеживайте глубину очереди мёртвых заданий как полноценную метрику. Её рост — самый ранний сигнал сломанной зависимости.

## Мониторинг того, что важно

Длина очереди сама по себе обманчива: здоровая пропускная способность с растущей задержкой хуже короткого всплеска. Смотрите на глубину, долю ошибок и возраст заданий вместе.

## Разделяйте очереди по приоритету

Долгие импорты не должны морить голодом сброс паролей. Маршрутизируйте по назначению, чтобы медленный пакетный процесс не задерживал пользовательскую работу.
