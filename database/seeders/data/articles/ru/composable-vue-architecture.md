Большой Vue-компонент — это обычно три ответственности в одном файле: загрузка данных, состояние и представление. Композаблы позволяют разделить их, не изобретая стор.

## Делите по ответственности

Каждый композабл владеет одной заботой и предоставляет узкий типизированный интерфейс. Компонент становится тонким шаблоном поверх них.

```ts
export function useArticle(slug: Ref<string>) {
    const article = ref<Article | null>(null);
    const loading = ref(false);

    watchEffect(async () => {
        loading.value = true;
        article.value = await fetchArticle(slug.value);
        loading.value = false;
    });

    return { article, loading };
}
```

> [!TIP]
> Если композабл возвращает больше нескольких ref-ов, он делает слишком много. Разделите его.

## Тестируйте логику, а не DOM

Композаблы — обычные функции. Vitest проверяет их без монтирования компонента.

| Слой | Чем тестируется |
| --- | --- |
| Композаблы | Vitest |
| Компоненты | Vitest + Testing Library |
| Страницы | Playwright |

## Композабл или стор?

Используйте стор только когда состояние действительно общее для несвязанных маршрутов. Локальное состояние живёт в композабле.

> [!TRADEOFF]
> Композаблы разбрасывают состояние по сравнению с единым стором. Награда — каждую часть можно понять изолированно.

## Имена — это API

`useArticle`, `useArticleFilters`, `useArticleReactions` точно описывают, чем владеют. Композабл с именем `useData` не владеет ничем.
