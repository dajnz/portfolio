Каждое изменение схемы, выполняемое во время деплоя, конкурирует с живым трафиком за одну и ту же таблицу. Паттерн «расширить — перенести — сжать» убирает эту гонку.

## Почему одна миграция опасна

`ALTER TABLE ... ADD COLUMN ... NOT NULL DEFAULT` переписывает таблицу и берёт блокировку. На большой таблице это простой, а не миграция.

| Изменение | Безопасно напрямую? |
| --- | --- |
| Добавить nullable-колонку | да |
| Добавить индекс concurrent | да |
| Переименовать колонку | нет |
| Сменить тип | нет |

> [!WARNING]
> Миграция, берущая эксклюзивную блокировку на горячую таблицу, останавливает всё приложение, а не только деплой.

## Расширение

Добавьте новую колонку как nullable и начните писать в старое и новое поля одновременно.

```sql
ALTER TABLE projects ADD COLUMN slug_new varchar(255);
```

## Перенос

Заполняйте пакетами, чтобы журнал транзакций не взорвался.

```sql
UPDATE projects SET slug_new = slug
WHERE id IN (SELECT id FROM projects WHERE slug_new IS NULL LIMIT 1000);
```

## Сжатие

Когда все читатели используют новую колонку, удалите старую в следующем релизе.

> [!TIP]
> Выпускайте расширение и сжатие отдельными деплоями. Промежуток между ними — ваше окно отката.

## Откаты

Поскольку каждый шаг обратно совместим, достаточно откатить приложение — откат схемы посреди инцидента не нужен.
