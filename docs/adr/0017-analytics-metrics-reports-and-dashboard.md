# ADR-0017: Analytics: privacy, metrics, reports & dashboard

- **Status:** Accepted
- **Date:** 2026-10-09
- **Source:** archived implementation plan (§2), IDs: A9, B4, B24, B25, B30, B32, B33, B283, B284, B285, B286, B287, B288, B289, B290, B291, B292, B293, B294, B295, B296, B297, B342
- **Supersedes:** —

## Context

Analytics needed privacy-safe tracking, a defined ingestion API, and an admin dashboard/reports surface. The original opaque event/report model contained correctness gaps (read time and CTA counts never populated) and mixed period-based reporting, so a typed event pipeline and a daily-metric reporting model were adopted.

## Decision

- **Privacy hashing (B4):** all keyed HMAC-SHA256 (IP hashes, feedback/reaction fingerprints) uses `config('analytics.ip_hash_key')` falling back to `APP_KEY`; fingerprint = HMAC of `ip|user_agent`; IP-only hash for `ip_address` columns.
- **Ingestion (B24, B25, B30):** `useAnalytics` posts to `/api/analytics/track`; any invalid event item rejects the entire batch. When the request User-Agent matches `NOT_BOT_USER_AGENT_PATTERN` the whole batch is discarded and the endpoint returns `204`. When the `MAX_BUFFER_SIZE_BYTES` (45 KB) cap is exceeded the newest events are dropped.
- **Typed events (B287, B289):** abstract `AnalyticsEvent` base + 7 concrete types (`PageViewEvent`, `TimeOnPageEvent`, `CallToActionClickEvent` with the `CallToActionTarget` enum github/demo/cv/feedback, `LanguageSwitchEvent`, `ThemeSwitchEvent`, `ArticleReadEvent`, `ArticleReactionEvent`). Event-specific data serializes via `toEventSpecificData()`; `AnalyticsEventFactory` is the single parse/dispatch table (unknown/malformed payloads are skipped on reads and reject the batch with 422 at ingestion). One event repository (events are write-mostly).
- **Page context (B289):** every event carries `page_type` (`PageType` enum: landing/blog_index/blog_article/projects_index/project_detail/experience, nullable) + `page_entity_id` (nullable), stored in `analytics_events.page_type`/`page_entity_id` and modeled by the `PageDetails` VO. The frontend `usePageTracking(type, entityId?)` + module-level `setPageContext` supply it; backend URL matching is gone and reports attribute via `toBlogArticleId()`/`toProjectId()`.
- **Daily metrics (B290):** the periodic report pipeline is replaced by a daily-only one. Raw events aggregate into `analytics_daily_metrics` — one row per `(metric, date, dimension)`, normalized, no JSONB; sum + samples (exact averages) and plain min/max are stored, kept forever.
- **Reports & spans (B290, B288):** `analytics_reports` holds per-metric aggregates over the metrics, pre-computed for every span (`day|week|month|year|all`; `all` = whole-time single row; rankings = `span=all` + dimension rows) and fully rebuilt from metrics on every generation. Reports expose typed results (`ReportScalarValue`/`ReportSeriesValue`/`ReportTableValue`) through one `AnalyticsReportRepositoryInterface` (`save`/`all`/`findNewestBefore`); entity constructors perform the aggregation, and `toResults()` is the single accessor.
- **Commands (B290):** daily `analytics:generate-daily-metrics` (`0 2 * * *`, supersedes the everyFourHours schedule) aggregates the previous day + the in-progress day and rebuilds reports. Manual `analytics:generate-reports` is a full rebuild: delete reports, recompute metrics for the still-present event window (oldest event → today) plus the full feedback history (never pruned), then rebuild reports; metrics older than the event window survive.
- **Dashboard (A9, B32, B291, B294):** three tabs (Overview/Blog/Projects); the feedback tab was removed and its submissions chart moved under Overview. Count cards exclude trashed content; "Total Views" = `SUM(article_views.views)` across all articles (incl. unpublished + trashed); "Blog Views" = published, non-soft-deleted only. The `analytics_report_frequency` setting was removed from `SettingName`, `SettingsSeeder`, the Settings → Analytics tab and the settings contract; the email toggle + recipient remain.
- **Charts & rankings (B292, B293, B295, B296):** the chart span dropdown offers daily/weekly/monthly/whole time. Each span renders a dense calendar window ending at the current period — daily the last 30 days, weekly the last 12 weeks, monthly the last 12 months (yearly the last 12 years), zero-filling the periods without stored rows; the multi-series union x-axis sorts its labels chronologically and thins them (plus the single-series value labels) to a readable stride. "Whole time" renders the cumulative running total from `span=day` rows, bucketed at the finest of day/week/month/year whose full history fits 30 points, anchored on the metric-wide oldest day so every CTA dimension shares one bucket sequence. `GET /admin/analytics/rankings?metric=&variant=top|bottom` returns top/bottom 10 (`span=all`, dimension rows); reactions use `variant=liked|disliked`. Clicking the CTA block renders one multi-series chart (all six CTA types + legend) via `AnalyticsChart`'s `series` prop (mutually exclusive with `data`); metric blocks show avg/min/max and open the ranking view on click. Chart + ranking data load via JSON endpoints on block click / dropdown change; Inertia props carry only the blocks + default chart + default rankings.
- **"Generate Now" (A9, B284):** `POST /admin/analytics/generate-reports` (auth + admin gated, operationId `analyticsGenerateReports`) dispatches the async rebuild and answers 202 `{"dispatched": true}`; the UI reloads on completion.
- **Email digest (B297):** `SendAnalyticsReportMail`, dispatched by `AggregateDailyMetricsJob`, carries the previous day's key metrics (views, unique visitors, feedback submissions, top article).
- **Observability (B342):** `TrackEventUseCase` emits the analytics batch entry on the `analytics` log channel.

## Consequences

- Period reports are derived from the daily metrics rather than pre-aggregated per period; only the manual command recomputes metrics, and only within the retained event window (feedback history excepted).
- Stored report payloads are the serialized typed results, deviating from the flat `data` structures in `analytics.md`; the inertia `data` field is free-form, so no OpenAPI contract change is needed.
- Legacy/unknown event rows are skipped on reads — everything stored must be typed and parseable, and report entities own their aggregation and payload invariants.
